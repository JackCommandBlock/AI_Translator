一、输入与总体目标

输入：

原始视频文件：包含内嵌原始字幕，但部分片段可能只有语音而没有字幕。
预处理后的 ASS 文件：已经包含完整的时间轴、样式、位置等信息，但没有实际字幕文本。

输出：

成品 ASS 字幕文件。
原 ASS 的时间轴、样式、位置、ASS 特效标签等信息原则上保持不变，仅补充或替换字幕文本。

核心原则：
ASS 文件负责提供“时间轴和排版”，视频负责提供“原始字幕文本和语音信息”，OCR 和 ASR 用于提取原文，翻译模块负责将原文转换为目标语言。

二、读取和解析 ASS

读取预处理后的 ASS 文件，解析所有 Dialogue 事件。

每个字幕事件至少记录：

Event ID
开始时间
结束时间
Layer
Style
Name
MarginL
MarginR
MarginV
Effect
Text

其中 Start 和 End 是后续所有识别和匹配工作的主要时间基准。

程序应尽量保留原 ASS 文件中的所有内容，最终只修改 Dialogue 的 Text 部分。

三、从视频中提取原始字幕

由于视频已经包含内嵌字幕，首先使用 OCR 从视频画面中提取原始字幕。

处理流程：

根据 ASS 时间轴确定需要识别的时间段。
从对应时间段提取若干代表性视频帧。
对视频帧进行字幕区域裁剪。
对字幕区域进行图像预处理。
使用 OCR 识别字幕文字。
综合多个帧的 OCR 结果，得到最终原文。
OCR提供置信度，置信度过低时，调用语言模型进行处理

不需要对视频的每一帧进行 OCR，可以在每个字幕事件的开始、中间和结束附近抽取少量帧进行识别。

如果 ASS 已经提供字幕位置，可以利用 ASS 的位置信息确定 OCR 区域。

四、语音识别

提供开关允许关闭语音识别，此时跳过所有与语音识别相关的步骤。

对于 OCR 无法识别的字幕事件，需要使用 ASR 从视频音频中恢复原文。

推荐流程：

从视频提取音频。
转换为适合语音识别的音频格式。
使用 Whisper/faster-whisper 等模型进行整段语音识别。
获取带有开始时间和结束时间的 ASR 结果。
根据时间轴将 ASR 结果匹配到 ASS Event。

ASR 应尽量对整段视频进行识别，而不是逐个 ASS Event 单独进行识别，因为一句话可能跨越多个字幕事件。

五、OCR 与 ASR 时间轴匹配

以 ASS Event 的时间轴作为主要时间轴，将 OCR 和 ASR 结果匹配到对应 Event。

例如：

ASS：
10.00～13.00

ASR：
10.50～12.80

则将该 ASR 结果匹配到对应 ASS Event。

匹配时可以综合考虑：

时间重叠长度
时间重叠比例
IoU
两个片段之间的时间距离

对于一句语音跨越多个 ASS Event 的情况，不应简单地把整句话复制到每一个 Event，而应该建立字幕组，在上下文层面处理。

六、确定原始字幕文本

根据 OCR 和 ASR 结果确定每个字幕事件的原文。

基本优先级：

OCR 成功且置信度较高：
使用 OCR 结果。
OCR 无法识别：
使用 ASR 结果。
OCR 与 ASR 均存在：
比较两者是否一致。
如果一致，直接确认。
如果存在差异，交给语言模型判断。
OCR 和 ASR 均无法可靠识别：
标记为需要人工审核，不强行生成结果。

每条原文最好记录：

文本
来源（OCR / ASR / OCR+ASR）
置信度
对应 ASS Event
对应时间范围

七、字幕上下文分组

翻译时不能始终按照单个 Event 独立翻译。

对于连续字幕，需要根据时间和语义建立字幕组。

例如：

Event 1：10.00～12.00
Event 2：12.00～14.00
Event 3：14.00～16.00

如果三者实际上构成一句完整的话，应作为一个整体进行翻译。

处理流程：

ASS Event
→ 判断连续性
→ 建立字幕组
→ 合并原文
→ 上下文翻译
→ 再将译文分配回原来的 Event

八、原文纠错

OCR 和 ASR 得到的文本可能存在识别错误。

例如 OCR：
今日はいい天気てすね

正确文本：
今日はいい天気ですね

可以利用以下方式进行纠错：

OCR 多帧结果投票
OCR 与 ASR 结果对比
日语语言模型
LLM 上下文纠错

纠错时应尽量避免改变原意。

九、自动翻译

将确认后的原文发送给翻译模块。

推荐批量翻译，而不是逐条调用翻译接口。

翻译输入应包含：

当前字幕原文
前后字幕上下文
字幕 Event ID
术语表
必要的角色或作品背景信息

翻译要求：

保持 Event ID 不变。
保持字幕顺序。
不输出额外解释。
保持人物称呼统一。
保持专有名词统一。
根据上下文进行翻译。
控制译文长度。
不修改 ASS 特效标签。

十、术语表

建立独立的术语表，用于保证整部视频或整个项目中的翻译一致性。

例如：

ゲッコウガ → 甲贺忍蛙
スマブラ → 任天堂明星大乱斗
先輩 → 前辈

翻译时将术语表作为额外约束。

术语表可以使用 JSON、CSV 或数据库保存。

十一、ASS 特效标签处理

ASS Text 中可能包含大量特殊标签，例如：

{\an8}
{\pos(960,100)}
{\fs40}
{\bord2}
{\fad(200,200)}
{\c&HFFFFFF&}

这些内容不能交给翻译模型直接修改。

处理方法：

从字幕文本中提取 ASS 标签。
将标签和普通文本分离。
只翻译普通文本。
翻译完成后重新组合标签和译文。

例如：

原文：

{\pos(960,900)\fs40}こんにちは

翻译后：

{\pos(960,900)\fs40}你好

十二、换行处理

ASS 中的 \N、\n 等换行符需要特殊处理。

原文：

これは本当に\Nすごいですね

翻译时需要保留换行结构，或者根据目标语言重新进行合理断句。

不能因为翻译而破坏 ASS 换行控制符。

十三、译文长度检查

翻译完成后，对每条字幕进行检查。

检查项目：

字符数量
每行长度
总显示时间
字幕区域宽度
是否存在过长文本
是否存在空文本

如果译文过长，可以进行：

自动重新断句。
自动压缩译文。
根据上下文重新翻译。
标记人工审核。

十四、生成最终 ASS

以原始预处理 ASS 为模板。

原则上只修改 Dialogue 的 Text 内容，保留：

时间轴
Layer
Style
Name
Margin
Effect
ASS 特效标签
Script Info
Styles
其他 ASS 设置

最终生成：

translated.ass

例如：

原始：

Dialogue: 0,0:00:10.00,0:00:13.00,Default,,0,0,0,,こんにちは

最终：

Dialogue: 0,0:00:10.00,0:00:13.00,Default,,0,0,0,,你好

十五、自动检查

生成 ASS 后进行自动质量检查。

主要检查：

是否存在空字幕。
是否存在无法识别的字幕。
是否存在未翻译的原文。
是否存在异常长字幕。
是否存在异常短字幕。
是否存在时间轴错误。
是否存在损坏的 ASS 标签。
是否存在翻译结果数量与原 Event 数量不一致。
是否存在 OCR/ASR 低置信度结果。
是否存在 OCR 和 ASR 结果冲突。

十六、人工审核

对于无法可靠自动处理的内容，进入人工审核列表。

重点审核：

OCR 低置信度。
ASR 低置信度。
OCR 与 ASR 不一致。
没有字幕但存在语音。
翻译过长。
翻译结果异常。
专有名词识别错误。
ASS 标签异常。

可以提供：

确认
修改
跳过
重新翻译

等操作。

十九、核心数据流

视频负责：
原始字幕 + 语音

OCR负责：
从画面获取原始字幕

ASR负责：
补充没有画面字幕的语音

ASS负责：
时间轴 + 样式 + 排版

Alignment负责：
将 OCR/ASR 文本对应到 ASS Event

翻译模块负责：
原文 → 目标语言

ASS Writer负责：
将译文写回原始 ASS

Quality Checker负责：
检查自动处理结果

最终原则：

ASS 是时间轴和排版的权威来源；
OCR 和 ASR 是原文的来源；
翻译模块只负责语言转换；
最终输出尽量只修改 ASS 的字幕文本，不破坏原有时间轴和样式。
